# Source privacy build gate

`Directory.Build.targets` runs `scripts/verify-source-privacy.py` before ordinary app/test builds and publish, including publish without rebuilding. Git and Python 3 are required build tools. Missing tools, an unreadable repository or an unsupported input fail the check; IDE design-time loading does not run it.

The check reads current working contents listed by Git: tracked files plus untracked nonignored source awaiting a checkpoint. Ignored local credentials, settings, private reports, build output and VM disks are excluded. This is a current-source guard; it neither inspects nor rewrites commit history.

Literal Windows profile paths, including doubled backslashes, forward slashes, Unicode escapes and URL-encoded forms, fail the build. Email-shaped values (including quoted/Unicode local parts) fail unless they use reserved example/test domains or match an explicit reviewed file/address entry in `scripts/source-privacy-examples.json`. The existing inert SMTP-provider tests and field placeholder keep their behavior. The policy is never expanded automatically when a check fails; new exceptions require deliberate review.

All current file types are inspected as UTF-8 and both UTF-16 byte orders, including ASCII metadata in binary assets. Linked/outside inputs or files above 32 MiB fail closed instead of being silently skipped. Diagnostics show file, line and category, without printing the identifying value. This pattern check does not certify absence of arbitrary secrets, encoded/compressed payloads or identifying information in Git history/commit metadata.

The terminal comment now describes generic profile folders. Session path decoding uses the executing user's profile and a spaced demo project; non-Windows hosts retain a Windows-shaped parser fixture based on the test-folder name. Fence command/sweep examples use a repository test-folder path with spaces; generic Public-directory assertions derive their location from Windows.
